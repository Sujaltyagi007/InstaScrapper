# Project context — read before exploring code

`brain.md` is the project's orientation doc: architecture, verified findings, known traps, and a "Recent changes" log. It is imported below, so its contents are already in context at the start of every session.

- **Use brain.md before opening code.** Don't re-explore the codebase to rediscover what it already says. Open code files only for the specific area you are changing.
- **Trust but verify.** If brain.md names a file, function or flag you're about to rely on, confirm it still exists before building on it.
- **After any meaningful change, update brain.md in the same turn:** add a dated entry at the top of "Recent changes" (newest first, keep ~15 entries), and edit the relevant section if behaviour or architecture changed. Correct statements that turn out wrong instead of adding contradictions.
